# Метеоритный рейс

Браузерная игра в жанре «астероидная оборона»: порт версии на Python/Pygame (`game.py`).
Вся графика рисуется процедурно на Canvas, весь звук генерируется через Web Audio API —
в проекте нет ни картинок, ни аудиофайлов, ни зависимостей, ни шага сборки.

## Играть

**https://eeealesha.github.io/meteorite-raid-game/**

## Управление

| Клавиша | Действие |
| --- | --- |
| `←` `→` | движение корабля |
| `Space` | огонь |
| `P` | пауза (также автоматически при потере фокуса окна) |
| `Esc` | выход в меню |

С телефона или планшета — экранные кнопки: `◀` `▶` внизу слева, `❚❚` (пауза) и
`ОГОНЬ` внизу справа. Кнопки не перекрывают игровое поле и не мешают игре
с клавиатуры. Играть удобнее в альбомной ориентации.

## Что в игре

- три сектора по 30 секунд с баннерами перехода и растущей сложностью;
- финальный босс с полосой HP и второй фазой на 50% здоровья;
- бонусы из уничтоженных астероидов: щит (гасит одно попадание) и двойной выстрел
  на 10 секунд (повторный подбор обновляет таймер);
- пауза по `P` и автопауза при потере фокуса — возобновление только действием игрока;
- итоговый экран с рекордом, который хранится в `localStorage` браузера;
- звук стартует после первого действия игрока, есть кнопка отключения;
- адаптация под телефон: экранные кнопки, поля под вырез экрана, `100dvh`-вёрстка.

Рекорд у каждого игрока свой: это локальное хранилище браузера, общего лидерборда нет.

## Устройство репозитория

```
game.py          — исходная игра на Python/Pygame (эталон, не изменяется)
browser/         — браузерная версия: статические HTML/CSS/JS, точка входа index.html
.github/workflows/pages.yml — публикация на GitHub Pages
запрос.rtf       — изначальное задание
```

Подробности по модулям, режиму проверки (DEBUG) и локальному запуску — в
[`browser/README.md`](browser/README.md).

## Локальный запуск

```bash
cd browser
python3 -m http.server 8000
# http://localhost:8000/
```

Подойдёт любой статический сервер. Политики браузера надёжнее работают с HTTP,
чем с открытием `index.html` напрямую из файловой системы.

## Публикация

Каждый push в `main` запускает workflow: он берёт содержимое `browser/` и публикует
его на GitHub Pages (без сборки, без зависимостей). Поэтому в корне сайта лежат файлы
из `browser/`, и адрес игры — без `/browser/` в пути. Все пути внутри игры относительные,
так что она работает и в любой подпапке.
